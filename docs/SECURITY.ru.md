# Модель безопасности KuzTDS

Нормативный документ: требования + что уже сделано (✅) и что запланировано (⏳).
Актуально на 2026-06-07. Остаток — в `TODO.md`.

## 1. Сериализация и ввод
- ✅ **Нет десериализации недоверенных данных** — только JSON
  (`encoding/json`), результат в фиксированный struct.
- ✅ Входные IP — через `netip.ParseAddr`; невалидные не попадают в запросы.
- ✅ Режим `?api=` — base64(**JSON**), доступ по ключу `KUZTDS_API_KEY`.
- ⏳ Подпись пакованных параметров `[ex]` HMAC-SHA256 — НЕ реализована; доп. GET-параметры идут как есть в `[PAR-n]`.

## 2. Доверенные прокси и IP клиента
- ✅ `server.RealIP`: доверяет `X-Forwarded-For`/`CF-Connecting-IP` только если
  `RemoteAddr` входит в `KUZTDS_TRUSTED_PROXIES` (CIDR); берёт правый недоверенный
  адрес из XFF (CF-Connecting-IP приоритетнее). Иначе — `RemoteAddr`.
- ✅ `CF-IPCountry` используется как источник страны (имеет смысл за доверенным edge).
- ⏳ Авто-обновление списка Cloudflare CIDR (сейчас задаётся статически в env).

## 3. Аутентификация админки
- ✅ Пароли: `argon2id` (`golang.org/x/crypto/argon2`).
- ✅ Смена пароля в UI (`POST /api/password`), хэш в `KUZTDS_ADMIN_PASSWORD_FILE`.
- ✅ Сессии: токен 256 бит (`crypto/rand`), хранение в Redis (TTL) или in-memory.
- ✅ Cookie: `HttpOnly`, `Secure` (конфиг), `SameSite=Strict`, ограниченный срок.
- ✅ CSRF: double-submit токен на небезопасных методах (POST/PUT/DELETE).
- ✅ Rate-limit логина: Redis sliding window; без блокирующего `sleep`.
- ⏳ Принудительная смена дефолтного пароля при первом старте.
- ⏳ TOTP (RFC 6238) и IP-allowlist админки.

## 4. Запросы к данным
- ✅ ClickHouse: только параметризованные запросы / типизированный batch insert;
  измерения breakdown — по белому списку колонок (не из ввода).
- ✅ Redis: ключи из валидированных идентификаторов (group/stream id).
- ✅ Имена файлов `.dat` валидируются (`^[a-zA-Z0-9._-]+\.dat$`, без `..`);
  ключи/даты в `/api/keys` — по белому набору символов.

## 5. Секреты и данные
- ✅ Секреты — через переменные окружения `KUZTDS_*`, не в коде/VCS.
- ✅ `.gitignore` исключает `*.local.yaml`, `*.env`, `secrets/`, `*.mmdb`, `.dat`
  (исключение — тестовая `internal/geo/testdata/*.mmdb`).
- Конфиг групп — JSON-файл `KUZTDS_GROUPS_FILE` (не yaml); пример — `configs/*.json`.

## 6. Сеть и заголовки
- ✅ Security-заголовки админки: `X-Content-Type-Options: nosniff`, `Referrer-Policy`.
- ✅ Таймауты на внешние вызовы (CURL-редирект, `[REMOTE]`, PTR-lookup).
- ✅ Ограничение размеров тел запросов (MaxBytesReader); экспорт логов лимитирован.
- ⏳ TLS+HSTS (терминируется на edge — деплой), CSP/`X-Frame-Options` для SPA.

## 7. Файловые операции
- ✅ Движок без web-doc-root → `.dat/.db/.ini` недоступны по HTTP в принципе.
- ✅ Пути к данным не формируются из пользовательского ввода (нет path traversal):
  группа по валидированному id, списки/ключи — по проверенным именам.
- ⏳ Загрузка обновлений IP-списков по HTTPS с проверкой подписи (часть cron-блока).

## 8. Процесс
- ✅ `go vet`, `go test` — зелёные; `govulncheck` — чисто (запускался вручную).
- ✅ Зависимости закреплены (`go.sum`); ошибки обрабатываются явно, структурные логи (slog).
- ⏳ CI-пайплайн (lint+test+vuln автоматически), `golangci-lint` в гейте.
