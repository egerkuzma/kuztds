## Что это

Система распределения трафика (TDS): принимает посетителя, по правилам решает,
куда его направить (редирект/iframe/JS/контент/заглушка), отделяет ботов от
людей, пишет статистику. Написана на Go ради скорости и безопасности.

Четыре исполняемых компонента:

| Бинарник | Назначение | Порт по умолчанию |
|----------|-----------|-------------------|
| `cmd/engine` | движок (горячий путь — обработка трафика) | 8080 |
| `cmd/admin` | REST API + веб-интерфейс администратора | 8090 |
| `cmd/cron` | фоновый сервис: обновление списков и гео-баз, VirusTotal, диск, Telegram | — |
| `cmd/apiclient` | клиент для лендинга/донора | 9090 |

Хранилища: **ClickHouse** (логи/конверсии), **Redis** (уникальность/лимиты/
фаервол/сессии). Оба опциональны — без них движок работает, пропуская
соответствующие проверки.

## Быстрый старт

```bash
# зависимости
brew install go docker
cd kuztds

# инфраструктура (ClickHouse + Redis), схема применяется автоматически
make infra-up

# хэш пароля админки
go run ./cmd/admin -hash 'мой-пароль'   # выведет $argon2id$...

# движок
KUZTDS_DATA_DIR=../database KUZTDS_GROUPS_FILE=configs/groups.example.json \
KUZTDS_TRUSTED_PROXIES=127.0.0.1/32 KUZTDS_POSTBACK_KEY=secret KUZTDS_API_KEY=apikey \
KUZTDS_REDIS_ADDR=localhost:6379 \
KUZTDS_CLICKHOUSE_ADDR=localhost:9000 KUZTDS_CLICKHOUSE_DB=kuztds \
KUZTDS_CLICKHOUSE_USER=kuztds KUZTDS_CLICKHOUSE_PASSWORD=devpassword \
go run ./cmd/engine

# админка (открыть http://localhost:8090, логин admin)
KUZTDS_ADMIN_PASSWORD_HASH='<хэш>' KUZTDS_ADMIN_PASSWORD_FILE=./admin.hash \
KUZTDS_ENGINE_URL=http://localhost:8080 KUZTDS_GROUPS_FILE=configs/groups.example.json \
KUZTDS_DATA_DIR=../database KUZTDS_KEYS_DIR=./keys \
KUZTDS_REDIS_ADDR=localhost:6379 KUZTDS_CLICKHOUSE_ADDR=localhost:9000 \
KUZTDS_CLICKHOUSE_DB=kuztds KUZTDS_CLICKHOUSE_USER=kuztds KUZTDS_CLICKHOUSE_PASSWORD=devpassword \
go run ./cmd/admin

# cron-сервис (опционально) — настраивается потом на странице Automation.
# Дай движку и админке те же KUZTDS_GEO_DB / KUZTDS_ASN_DB,
# а админке — тот же KUZTDS_CRON_FILE.
KUZTDS_CRON_FILE=./cron.json KUZTDS_DATA_DIR=../database KUZTDS_KEYS_DIR=./keys \
KUZTDS_GROUPS_FILE=configs/groups.example.json \
KUZTDS_GEO_DB=./geo/city.mmdb KUZTDS_ASN_DB=./geo/asn.mmdb \
KUZTDS_CLICKHOUSE_ADDR=localhost:9000 KUZTDS_CLICKHOUSE_PASSWORD=devpassword \
go run ./cmd/cron
```

## Переменные окружения

### engine
| Переменная | Назначение |
|------------|-----------|
| `KUZTDS_LISTEN` | адрес прослушивания (`:8080`) |
| `KUZTDS_DATA_DIR` | каталог `.dat`-списков (IP, wap, сигнатуры) |
| `KUZTDS_GROUPS_FILE` | JSON-конфиг групп (без него — встроенная demo) |
| `KUZTDS_TRUSTED_PROXIES` | CIDR доверенных прокси (для XFF/CF), через запятую |
| `KUZTDS_GEO_DB` | путь к City- или Country-базе `.mmdb` в формате MaxMind (GeoLite2, GeoIP2, DB-IP Lite). Без неё страна берётся из `CF-IPCountry`, а город/регион/часовой пояс неизвестны. Тестовые базы лежат в `internal/geo/testdata/` |
| `KUZTDS_ASN_DB` | путь к ASN-базе `.mmdb` в формате MaxMind; без неё условия по ASN / организации не срабатывают никогда |
| `KUZTDS_REDIS_ADDR` / `KUZTDS_REDIS_PASSWORD` | Redis (uniq/limit/firewall) |
| `KUZTDS_CLICKHOUSE_ADDR` / `_DB` / `_USER` / `_PASSWORD` | ClickHouse (логи) |
| `KUZTDS_POSTBACK_KEY` | ключ для `?pb=` постбэка |
| `KUZTDS_API_KEY` | ключ для режима `?api=` (api-клиенты) |
| `KUZTDS_KEYS_DIR` | каталог сбора ключевых слов |
| `KUZTDS_TRASH_MODE` / `KUZTDS_TRASH_URL` | поведение для неизвестной группы (0=200,1=redirect,2=403,3=404) |
| `KUZTDS_CURL_CACHE` | кэш CURL-редиректа, минут |
| `KUZTDS_CURL_UA` | User-Agent, с которым движок ходит за CURL / `[REMOTE]` |
| `KUZTDS_RELOAD_INTERVAL` | период hot-reload списков, групп и гео-баз (`1m`) |

### admin
| Переменная | Назначение |
|------------|-----------|
| `KUZTDS_ADMIN_LISTEN` | адрес (`:8090`) |
| `KUZTDS_ADMIN_USER` | логин (`admin`) |
| `KUZTDS_ADMIN_PASSWORD_HASH` | argon2id-хэш пароля |
| `KUZTDS_ADMIN_PASSWORD_FILE` | файл хэша (приоритетнее; туда пишется смена пароля в UI) |
| `KUZTDS_ADMIN_COOKIE_SECURE` | флаг Secure для cookie (`true`; локально `false`) |
| `KUZTDS_ENGINE_URL` | базовый URL движка (для ссылок групп в UI) |
| `KUZTDS_GROUPS_FILE` / `KUZTDS_DATA_DIR` / `KUZTDS_KEYS_DIR` | те же пути, что у движка |
| `KUZTDS_REDIS_ADDR` / `KUZTDS_CLICKHOUSE_*` | хранилища (сессии, статистика) |
| `KUZTDS_GEO_DB` / `KUZTDS_ASN_DB` | те же пути, что у движка — для Tools (проверка IP) и «Test a visitor» |
| `KUZTDS_CRON_FILE` | файл конфига cron-сервиса; без него страница Automation только для чтения |

### cron
| Переменная | Назначение |
|------------|-----------|
| `KUZTDS_CRON_FILE` | файл конфига (JSON, по умолчанию `cron.json`), пишется админкой. Состояние сервис хранит в `<file>.status.json`, запросы «запустить сейчас» берёт из `<file>.run` |
| `KUZTDS_DATA_DIR` / `KUZTDS_KEYS_DIR` / `KUZTDS_GROUPS_FILE` | те же пути, что у движка |
| `KUZTDS_GEO_DB` / `KUZTDS_ASN_DB` | куда пишется скачанная City- / ASN-база. Конфиг выбирает, что скачивать; пути назначения берутся только отсюда |
| `KUZTDS_CLICKHOUSE_*` | нужны только для уведомлений о конверсиях |

### apiclient
`KUZTDS_TDS_URL` (URL движка), `KUZTDS_API_KEY`, `KUZTDS_GROUP_ID`,
`KUZTDS_APICLIENT_LISTEN`, `KUZTDS_TRUSTED_PROXIES`, `KUZTDS_COOKIE` (имя cookie
уникальности, которую ставит клиент; по умолчанию `ztu`).

## Ссылки, которые отдаёт движок

- Группа: `http://домен/<id>` (и алиасы `http://домен/<alias>`)
- С ключевым словом: `http://домен/<id>?q=КЛЮЧ`
- С доп. параметрами: `http://домен/<id>?p1=...&p2=...` → макросы `[PAR-1..5]`
- Постбэк-пиксель: `http://домен/?pb=KEY&cid=[CID]&profit=1.50`
- Любая переменная строки запроса может быть условием потока («URL parameter»:
  `utm_source=fb` или просто `sub1` — «присутствует»).

Группа берётся из **первого сегмента пути**, всё после него игнорируется.
`/promo`, `/promo/` и `/promo/iphone-15-sale.html` одинаково попадают в группу
`promo` — ссылку можно замаскировать под настоящую страницу, и это не изменит
маршрут. Неизвестный первый сегмент уходит в trash-режим.

## Веб-интерфейс админки

Одна **верхняя панель**: навигация, выбор периода, переключатель темы, меню
пользователя (Settings, Log out). Сайдбаров нет; каждая страница занимает всю
ширину и имеет свой адрес (`#/flows/promo`, `#/tools/8.8.8.8`), так что
«назад/вперёд» и ссылки работают. Светлая и тёмная темы: кнопка солнце/луна
переключает и запоминает выбор в браузере (`localStorage`); пока выбор не
сделан, панель следует `prefers-color-scheme`.

**Сохранение.** Группы и настройки автоматизации правятся в рабочей копии и
сравниваются с последним сохранённым. Как только они расходятся, внизу любой
страницы появляется панель: **Save** (`Ctrl`/`Cmd`+`S`) или **Discard**.
Черновики переживают переходы между страницами; закрытие вкладки с
несохранёнными изменениями сначала спросит. Пустые, дублирующиеся и
некорректные ID групп отклоняются до отправки запроса.

Страницы: **Dashboard** (шесть плиток KPI — визиты, уникальные, боты,
конверсии, профит, CR; график по времени с подсказкой при наведении;
**таблица результативности** по группам → потокам из
`GET /api/stats/performance`, сортировка, CSV, строка открывает группу;
разбивки по странам / устройствам / ОС / браузерам / источникам / сетям),
**Flows** (ниже), **Logs** (фильтры — выпадающие списки с галочками, значения
подгружаются из данных за период через `GET /api/logs/filters`; поле IP;
люди/боты; CSV; строка открывает детали визита — маршрут, местоположение, сеть,
User-Agent, реферер), **Conversions**, **Keywords**, **Lists** (редактор
`.dat`), **Tools** (ниже), **Automation** (ниже), **Settings**.

### Flows

*Flow* — это группа из конфига. Список показывает по карточке на группу:
статус, визиты / боты / конверсии / профит за период, первые потоки и группы,
на которые она ссылается. Меню карточки включает/выключает группу, дублирует
или удаляет её.

**Страница группы** рисует её так, как её исполняет движок:

- **вход** наверху с числом посетителей;
- **ствол**, идущий вниз, — посетители спускаются по нему, поток за потоком;
- каждый **поток** — узел на стволе (номер, имя, переключатель, его условия
  чипами, его заметка) с **веткой** к назначению справа (тип, первая строка
  вывода, варианты, что получают боты);
- **выход по умолчанию** внизу — то, что получают все оставшиеся.

Толщина линий и подписи на ветках — трафик за выбранный период (количество и
доля), так что схема одновременно и отчёт: сколько забирает каждый поток и
сколько проваливается мимо.

Работа со схемой: поток **перетаскивается** за ручку, чтобы поменять порядок
(побеждает первое совпадение, так что порядок и есть логика); **переключатель**
выключает его на месте; меню **⋯** дублирует, переносит в другую группу или
удаляет; **+ Stream** добавляет новый; в шапке — живая ссылка с кнопкой
копирования, переключатель группы и выпадающий список для перехода к другой
группе.

**Редактор потока** — выдвижная панель поверх страницы: схема остаётся на
месте и обновляется под ней. Разделы:

1. **When** — только те условия, которые у потока есть, у каждого ✕; **Add
   condition** предлагает остальные: *Geo* — страна, город, регион, часовой
   пояс; *Network* — ASN, организация, мобильный оператор, IP-список; *Device*
   — тип, бренд, ОС, браузер, Яндекс.Браузер; *Request* — язык, реферер,
   наличие реферера, домен-источник, ключ, параметр URL, User-Agent; *Visit* —
   уникальность, дни недели, лимит показов. Списковые условия — `is` /
   `is not` плюс значения через запятую (`/regex/` не разрезается); пустое
   значение — условия нет.
2. **Then** — тип (шесть частых карточками, все — в списке), вывод со списком
   макросов, как чередуются несколько вариантов через `|||`. Выбор **Another
   flow** заменяет вывод выбором группы.
3. **Bots** — сигналы детекта переключателями, что получают боты, их
   Content-Type и вывод, добавлять ли обнаруженные IP в списки.
4. **Advanced** — шанс показа, переопределение Content-Type, separation,
   `[REMOTE]`, правила перезаписи для прокси, API mac. **Заметка** в конце
   показывается на схеме.

**Настройки группы** (тоже выдвижная панель): ID, имя, алиасы; выход по
умолчанию (тип, Content-Type, вывод — или другая группа); откуда берётся страна
(сначала заголовок CDN / сначала гео-база), уникальность (IP или cookie, окно в
часах), сбор ключей; антифлуд; ссылки, которые отдаёт движок; дублирование,
очистка залогированных визитов, удаление. Переименование группы обновляет
потоки, которые на неё ссылаются.

**Test a visitor** (кнопка на странице группы): IP-адрес, пресет устройства и,
по желанию, страна, язык, реферер, ключ, параметры URL, «returning visitor».
Ответ (`POST /api/simulate`) рисуется на схеме — путь зелёным, **matched** на
победившем потоке, а на каждом из остальных — условие, которое не пропустило
посетителя, подсвеченное среди его чипов; потоки ниже победителя, которые тоже
совпали бы, так и помечены. Используются группы в том виде, как они на экране,
сохранённые или нет, с переходами по ссылкам в другие группы. Лимиты показов,
проверки на ботов и антифлуд зависят от живого трафика и не симулируются.

### Tools

Введи IP-адрес (или перейди по «look up» из строки лога): страна, город,
регион, часовой пояс и смещение от UTC; ASN и организация; мобильный оператор;
в каких `.dat`-списках он есть; и какие гео-базы загружены, с датами их сборки.

### Automation

Страница cron-сервиса. Метка наверху показывает, работает ли сервис (он пишет
heartbeat раз в несколько секунд). Карточка на каждую задачу: переключатель,
настройки, интервал, последний результат с его временем и **Run now**.

| Задача | Что делает |
|--------|------------|
| Bot IP lists | Скачивает каждый источник в `.dat`-список. Источник с целью пишет этот список (обычные строки или JSON вида `{"prefixes":[…]}`, который публикуют Google и Bing); без цели файл делится по секциям `# google`, `# yandex`… на `ip_<имя>`. `replace` перезаписывает, `merge` только добавляет. Источник, не вернувший адресов, никогда не опустошает список |
| Geo databases | Скачивает City- и ASN-базы (`.mmdb`, `.mmdb.gz`, `.tar.gz`; basic auth для MaxMind: ID аккаунта + лицензионный ключ). Скачанное открывается и его тип проверяется до замены файла; движок перечитывает базу сам |
| VirusTotal | Спрашивает о каждом домене из выводов потоков (и о перечисленных вручную). О новых помеченных доменах сообщает один раз; по желанию потоки, ведущие на них, выключаются |
| Disk space | Предупреждает, когда свободное место падает ниже порога, и ещё раз — когда оно восстанавливается |
| Keyword cleanup | Удаляет файлы ключевых слов старше N дней |
| Conversion alerts | Отправляет каждый новый постбэк в Telegram по шаблону (`[PROFIT] [GROUP] [STREAM] [COUNTRY] [CITY] [DEVICE] [DOMAIN] [CID]`) |

Telegram (токен бота + ID чата) — канал уведомлений, с кнопкой **Send a
test**. Секреты никогда не отправляются обратно в браузер: сохранённый токен
или ключ показывается как `********`, и сохранение без изменения оставляет
хранимое значение.

## Конфиг групп (JSON)

Примеры: `configs/groups.example.json`, `configs/test_groups.json` (набор разных
групп для прогона трафика). Структура: массив групп `{id, name, status, redirect,
header, out, geo, uniq_method, uniq_seconds, firewall, save_keys, save_keys_se,
aliases, streams[]}`; поток `{name, status, comment, rules, out{redirect,out,
chance,distribution,header}, bots, separation, remote, api_mac, curl}`.

- `id` — идентификатор и адрес `/<id>`; `name` — опциональное отображаемое имя.
- Дефолты группы (`redirect`/`out`/`header`) применяются, если поток не задал своё.
- `geo` — какой источник страны побеждает, когда отвечают оба: `cf` = сначала
  заголовок CDN `CF-IPCountry`, всё остальное (`db`) = сначала гео-база; второй
  источник — запасной. Заголовку верят, только если запрос пришёл через прокси
  из `KUZTDS_TRUSTED_PROXIES`.
- `redirect: "group"` с `out: "<id>"` — у потока или как выход группы по
  умолчанию — передаёт посетителя в другую группу (до трёх переходов;
  отсутствующая или выключенная цель отвечает как неизвестная группа). Визит
  пишется в лог под той группой, которая его обслужила, и засчитывается также
  потоку, который его передал.
- Новые ключи правил: `asn` (номера, `AS15169` или `15169`), `org` (подстрока
  или `/regex/`), `timezone` (`+3`, `+5:30` или `Europe/Moscow`), `get`
  (`name` или `name=value`). `out.header` переопределяет Content-Type группы;
  `comment` — заметка для оператора.
- Редактируется через UI («Flows»: схема, редактор в выдвижной панели, одна
  панель сохранения). Движок перечитывает файл при изменении, по тикеру
  `KUZTDS_RELOAD_INTERVAL` (по умолчанию 1 мин) — правки и из UI, и внесённые в
  файл напрямую вступают в силу без рестарта. Файл, который не распарсился или
  пропал, пропускается и пробуется снова, работающий конфиг остаётся на месте.

## Макросы вывода

`[KEY] [PATH] [IP] [COUNTRY] [CITY] [REGION] [ASN] [ORG] [TIMEZONE] [UTC]
[LANG] [DEVICE] [OPERATOR] [DOMAIN] [USERAGENT] [CID] [PAR-1..5]
[()COUNTRY()] [()CITY()]
[RANDNUM-a-b] [RANDSTR-(набор)-n] [RANDLINE-(файл)-n[/u]] [RANDDFL-(каталог)-n[/u]]`

`[ASN]` — номер (пусто, если неизвестен), `[ORG]` — владелец сети
(url-кодированный, как `[KEY]`), `[TIMEZONE]` — имя зоны, `[UTC]` — текущее
смещение (`+3`).

## Особенности реализации

- Один долгоживущий процесс; IP-списки в памяти (поиск O(log n)).
- ClickHouse для логов/конверсий; Redis-счётчики для уникальности/лимитов/фаервола.
- Безопасность: argon2id, серверные сессии, CSRF, параметризованные запросы,
