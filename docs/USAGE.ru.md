# KuzTDS — руководство

## Что это

Система распределения трафика (TDS): принимает посетителя, по правилам решает,
куда его направить (редирект/iframe/JS/контент/заглушка), отделяет ботов от
людей, пишет статистику. Написана на Go ради скорости и безопасности.

Три исполняемых компонента:

| Бинарник | Назначение | Порт по умолчанию |
|----------|-----------|-------------------|
| `cmd/engine` | движок (горячий путь — обработка трафика) | 8080 |
| `cmd/admin` | REST API + веб-интерфейс администратора | 8090 |
| `cmd/apiclient` | клиент для лендинга/донора | 9090 |

Хранилища: **ClickHouse** (логи/конверсии), **Redis** (уникальность/лимиты/
фаервол/сессии). Оба опциональны — без них движок работает, пропуская
соответствующие проверки.

## Быстрый старт

```bash
# зависимости
brew install go docker
cd kuztds

# инфраструктура (ClickHouse + Redis), схема применяется автоматически
make infra-up

# хэш пароля админки
go run ./cmd/admin -hash 'мой-пароль'   # выведет $argon2id$...

# движок
KUZTDS_DATA_DIR=../database KUZTDS_GROUPS_FILE=configs/groups.example.json \
KUZTDS_TRUSTED_PROXIES=127.0.0.1/32 KUZTDS_POSTBACK_KEY=secret KUZTDS_API_KEY=apikey \
KUZTDS_REDIS_ADDR=localhost:6379 \
KUZTDS_CLICKHOUSE_ADDR=localhost:9000 KUZTDS_CLICKHOUSE_DB=kuztds \
KUZTDS_CLICKHOUSE_USER=kuztds KUZTDS_CLICKHOUSE_PASSWORD=devpassword \
go run ./cmd/engine

# админка (открыть http://localhost:8090, логин admin)
KUZTDS_ADMIN_PASSWORD_HASH='<хэш>' KUZTDS_ADMIN_PASSWORD_FILE=./admin.hash \
KUZTDS_ENGINE_URL=http://localhost:8080 KUZTDS_GROUPS_FILE=configs/groups.example.json \
KUZTDS_DATA_DIR=../database KUZTDS_KEYS_DIR=./keys \
KUZTDS_REDIS_ADDR=localhost:6379 KUZTDS_CLICKHOUSE_ADDR=localhost:9000 \
KUZTDS_CLICKHOUSE_DB=kuztds KUZTDS_CLICKHOUSE_USER=kuztds KUZTDS_CLICKHOUSE_PASSWORD=devpassword \
go run ./cmd/admin
```

## Переменные окружения

### engine
| Переменная | Назначение |
|------------|-----------|
| `KUZTDS_LISTEN` | адрес прослушивания (`:8080`) |
| `KUZTDS_DATA_DIR` | каталог `.dat`-списков (IP, wap, сигнатуры) |
| `KUZTDS_GROUPS_FILE` | JSON-конфиг групп (без него — встроенная demo) |
| `KUZTDS_TRUSTED_PROXIES` | CIDR доверенных прокси (для XFF/CF), через запятую |
| `KUZTDS_GEO_DB` | путь к MaxMind `.mmdb` (без него гео по CF-IPCountry). Для теста есть `internal/geo/testdata/GeoLite2-City-Test.mmdb` |
| `KUZTDS_REDIS_ADDR` / `KUZTDS_REDIS_PASSWORD` | Redis (uniq/limit/firewall) |
| `KUZTDS_CLICKHOUSE_ADDR` / `_DB` / `_USER` / `_PASSWORD` | ClickHouse (логи) |
| `KUZTDS_POSTBACK_KEY` | ключ для `?pb=` постбэка |
| `KUZTDS_API_KEY` | ключ для режима `?api=` (api-клиенты) |
| `KUZTDS_KEYS_DIR` | каталог сбора ключевых слов |
| `KUZTDS_TRASH_MODE` / `KUZTDS_TRASH_URL` | поведение для неизвестной группы (0=200,1=redirect,2=403,3=404) |
| `KUZTDS_CURL_CACHE` | кэш CURL-редиректа, минут |
| `KUZTDS_CURL_UA` | User-Agent, с которым движок ходит за CURL / `[REMOTE]` |
| `KUZTDS_RELOAD_INTERVAL` | период hot-reload `.dat` (`1m`) |

### admin
| Переменная | Назначение |
|------------|-----------|
| `KUZTDS_ADMIN_LISTEN` | адрес (`:8090`) |
| `KUZTDS_ADMIN_USER` | логин (`admin`) |
| `KUZTDS_ADMIN_PASSWORD_HASH` | argon2id-хэш пароля |
| `KUZTDS_ADMIN_PASSWORD_FILE` | файл хэша (приоритетнее; туда пишется смена пароля в UI) |
| `KUZTDS_ADMIN_COOKIE_SECURE` | флаг Secure для cookie (`true`; локально `false`) |
| `KUZTDS_ENGINE_URL` | базовый URL движка (для ссылок групп в UI) |
| `KUZTDS_GROUPS_FILE` / `KUZTDS_DATA_DIR` / `KUZTDS_KEYS_DIR` | те же пути, что у движка |
| `KUZTDS_REDIS_ADDR` / `KUZTDS_CLICKHOUSE_*` | хранилища (сессии, статистика) |

### apiclient
`KUZTDS_TDS_URL` (URL движка), `KUZTDS_API_KEY`, `KUZTDS_GROUP_ID`,
`KUZTDS_APICLIENT_LISTEN`, `KUZTDS_TRUSTED_PROXIES`, `KUZTDS_COOKIE` (имя cookie
уникальности, которую ставит клиент; по умолчанию `ztu`).

## Ссылки, которые отдаёт движок

- Группа: `http://домен/<id>` (и алиасы `http://домен/<alias>`)
- С ключевым словом: `http://домен/<id>?q=КЛЮЧ`
- С доп. параметрами: `http://домен/<id>?p1=...&p2=...` → макросы `[PAR-1..5]`
- Постбэк-пиксель: `http://домен/?pb=KEY&cid=[CID]&profit=1.50`

Группа берётся из **первого сегмента пути**, всё после него игнорируется.
`/promo`, `/promo/` и `/promo/iphone-15-sale.html` одинаково попадают в группу
`promo` — ссылку можно замаскировать под настоящую страницу, и это не изменит
маршрут. Неизвестный первый сегмент уходит в trash-режим.

## Веб-интерфейс админки

Оболочка: **сайдбар слева** (навигация с иконками), **топбар справа** (выбор
периода, переключатель темы, шестерёнка «Настройки», чип пользователя и кнопка
выхода). Стиль GitHub (Primer), **светлая и тёмная темы**: кнопка солнце/луна
переключает и запоминает выбор в браузере (`localStorage`); пока выбор не
сделан, панель следует `prefers-color-scheme`.

Разделы: **Дашборд** (шесть плиток KPI — визиты, уникальные, боты, конверсии,
профит, CR; график по времени с подсказкой при наведении: total — заливка,
unique — пунктир, боты — оранжевая линия; **таблица результативности** по
группам → потокам: хиты / уникальные / боты / конверсии / профит / CR из
`GET /api/stats/performance`, сортировка по любому столбцу, экспорт CSV,
строка «no match → group default» у каждой группы, группы, которых нет в
конфиге, помечены «not in config»; разбивки страны/устройства/ОС/браузеры/
источники), **Логи** (фильтры-**выпадающие списки с галочками**:
группа/поток/страна/устройство/OS/браузер/бренд — значения подгружаются из данных
за период `GET /api/logs/filters`, можно отметить несколько → SQL `IN`; плюс
поиск внутри списка, IP-поле, тип люди/боты, пагинация, экспорт CSV),
**Конверсии** (выбор группы, сумма и количество), **Ключи** (просмотр
собранных ключевых слов), **Группы** (дерево + водопад / редактор потока, ниже),
**Списки** (редактор `.dat`, в т.ч. WAP-операторы). «Настройки» (смена пароля,
тема) — по шестерёнке справа.

### Группы

Слева сворачиваемое дерево группа→поток (шеврон у группы) и поиск по именам
групп и потоков; у каждой группы и потока — хиты за выбранный период. Справа
панель, в которой открыто **ровно одно**: водопад группы или редактор одного
потока. Обе панели скроллятся внутри себя, страница не двигается — выбранное
всегда открывается на одном и том же месте.

**Водопад группы.** Потоки — это и есть логика маршрутизации, поэтому страница
группы — их список в том порядке, в каком движок их перебирает, по строке на
поток: номер и ручка для перетаскивания, переключатель вкл/выкл, имя, условия
чипами (`country ∈ ru`, `device phone`, `limit 50 / day`…; «any visitor», если
условий нет), стрелка к выходу (тип редиректа + первая строка `out`) и под ней
что получают боты (`bots → 404_not_found` или `bots → same`), и хиты / боты /
конверсии за период. Последняя, приглушённая строка — **no match**, выход
группы по умолчанию, со своими цифрами: видно, сколько трафика проваливается
мимо потоков. Строку можно перетащить (или ↑/↓ в редакторе потока), клик
открывает редактор, переключатель выключает поток на месте. В шапке — живая
ссылка с кнопкой копирования и итоги группы; **+ Stream** добавляет поток и
открывает его; **Settings** раскрывает над водопадом форму группы: ID / имя /
алиасы, активность, выход по умолчанию (тип редиректа, Content-Type, out с
макросами), источник гео, метод и окно уникальности, сбор ключей / из
поисковиков, антифлуд, ссылки движка и опасная зона (очистка логов, удаление
группы).

**Редактор потока.** В шапке имя, переключатель «enabled», ↑/↓ и Delete;
ссылка назад возвращает к группе. Две колонки:

- **When — условия.** Показаны только те условия, которые у потока заданы, у
  каждого ✕ для удаления; **Add condition** предлагает остальные по группам:
  *Geo* страна / город / регион; *Device* тип устройства (компьютеры / телефоны /
  планшеты чипами-разрешениями), бренд, WAP-оператор; *Browser / OS* ОС,
  браузер, Яндекс.Браузер; *Text* User-Agent, Referer, домен, ключ, язык;
  *Other* IP-список, уникальность, наличие referer, расписание, лимит показов.
  Списковые условия — `include` / `exclude` плюс значения через запятую (один
  `/regex/` не разрезается); пустое значение = фильтра нет.
- **Then — выход.** Тип редиректа, распределение (для вариантов через `|||`),
  out со списком макросов. **Bots**: сигналы детекта чипами-переключателями, что
  отдавать ботам (как людям или любой тип редиректа), Content-Type и out для
  ботов, дописывать IP ботов в список. **Advanced** (свёрнут, пока там ничего не
  задано): шанс показа, файл separation, `[REMOTE]`, CURL find/replace для людей
  и ботов, API mac.

Правки живут в браузере до кнопки **Save** (работает и `Ctrl`/`Cmd`+`S`). В
шапке панели загорается метка «unsaved», а уход из раздела или закрытие вкладки
сначала спросят подтверждение; смена периода при несохранённых правках только
обновляет цифры. Пустые и дублирующиеся ID групп отлавливаются до отправки
запроса.

UI — один встроенный файл (`internal/admin/web/index.html`, `go:embed`). Тесты:
`internal/admin/web_test.go` (отдача SPA + структурные якоря + ключевые функции),
а проверка синтаксиса встроенного JS — `go test -tags=uitest ./internal/admin/`
(нужен node; одна опечатка в скрипте обрушивает весь SPA — этот тест её ловит).

Семантика флагов фильтров: **выключено / исключать (чёрный список) / отбирать
(белый список)**.

## Конфиг групп (JSON)

Примеры: `configs/groups.example.json`, `configs/test_groups.json` (набор разных
групп для прогона трафика). Структура: массив групп `{id, name, status, redirect,
header, out, geo, uniq_method, uniq_seconds, firewall, save_keys, save_keys_se,
aliases, streams[]}`; поток `{name, status, rules, out{redirect,out,chance,
distribution}, bots, separation, remote, api_mac, curl}`.

- `id` — идентификатор и адрес `/<id>`; `name` — опциональное отображаемое имя.
- Дефолты группы (`redirect`/`out`/`header`) применяются, если поток не задал своё.
- Редактируется через UI («Группы»: дерево слева, форма справа,
  «Сохранить всё»). Движок перечитывает файл при изменении, по тикеру
  `KUZTDS_RELOAD_INTERVAL` (по умолчанию 1 мин) — правки и из UI, и внесённые в
  файл напрямую вступают в силу без рестарта. Файл, который не распарсился или
  пропал, пропускается и пробуется снова, работающий конфиг остаётся на месте.

## Макросы вывода

`[KEY] [PATH] [IP] [COUNTRY] [CITY] [REGION] [LANG] [DEVICE] [OPERATOR]
[DOMAIN] [USERAGENT] [CID] [PAR-1..5] [()COUNTRY()] [()CITY()]
[RANDNUM-a-b] [RANDSTR-(набор)-n] [RANDLINE-(файл)-n[/u]] [RANDDFL-(каталог)-n[/u]]`

## Особенности реализации

- Один долгоживущий процесс; IP-списки в памяти (поиск O(log n)).
- ClickHouse для логов/конверсий; Redis-счётчики для уникальности/лимитов/фаервола.
- Безопасность: argon2id, серверные сессии, CSRF, параметризованные запросы,
  только JSON, доверенные прокси для XFF.
- Уникальность «по cookie»: выделенная cookie с корректным TTL.
